# 影视打斗与VFX配方

核心原则：**先懂原片，再谈特效；先出方案占位，用户确认后才花生成预算**。特效要贴合原片的动作节奏与镜头语言，不是贴图层。

工具：`video_understand`（析原片）+ `bash`（pandoc 读特效要求、ffmpeg 分段/合成）+ `view_image`（看关键帧）+ `video_generate`（reference_video 锁原片动作 / first_frame 图生视频）+ `ask`（收敛确认）+ `mossland_prepare_generation`（用户要求占位时改为排队，由用户执行）。

## 阶段序列

1. **析**（不生成）—
   - `video_understand` 完整分析上传视频：时间轴上的**动作节拍**（每一次交锋/起势/受击/环境互动）、镜头切换点、运镜方式、人物与场景、光线与色调基调；
   - `bash` 用 `pandoc -t plain` 读特效要求文档（.docx）；若无文档则以用户文字要求为准；
   - 输出**特效清单**：要加什么（火花/剑气/冲击波/粒子/光效/环境破坏…）、加在哪个时间点/哪段动作上、为什么（服务打击感还是氛围），以及哪些要求超出当前生成能力需要降级或用剪辑手段替代（如实说明）。

2. **段**（不生成）—
   - 用 `ffmpeg` 按动作节拍把原片切成若干段，**每段 ≤5s**、切口落在动作间歇处，落盘 `generated/segments/seg_<n>.mp4`；
   - `ffmpeg` 抽每段首帧作关键帧（`seg_<n>_f0.png`），`view_image` 复核；
   - 在回复里列出**分段表**：段号 / 时间码 / 动作内容 / 计划的特效。

3. **案**（不生成）— 逐段给出**占位方案清单**（编号列表）：
   - 每段写明：生成方式（**视频生视频**：reference_video=该段原片，保动作与构图；或**图生视频**：first_frame=该段首帧，保画面起点）+ **完整特效提示词**（画面内容 + 特效细节 + 与原片一致的镜头/光线措辞）+ 时长；
   - 主动给出**成本建议**：先做 1 个试点段验证风格与贴合度，通过后再批量；
   - 此阶段**不调用 video_generate**。让用户先审方案与提示词。

4. **做**（定点生成）— `ask` 确认后执行：
   - 先生成**试点段**（选特效最典型的一段），给用户看效果；
   - 试点通过后再逐段生成其余段；每段失败/跑偏时只重做该段，提示词按用户反馈修订后重试；
   - 若用户明确表示"由我来执行生成"，则全部改用 `mossland_prepare_generation` 排队（generator: video），只交提示词与参数，不直接生成。

5. **合**（本地合成，不花生成预算）—
   - `ffmpeg` concat 全部通过验收的分段，**保留/移植原片音轨**（或按要求混入新音效），对齐时长与帧率；
   - 输出 `generated/final/vfx_<原名>.mp4`，回复里说明哪些段落重做过、接缝在哪，请用户整片验收。

## 门禁
- 阶段 1-3 绝不生成：分析、分段表、逐段占位方案必须先落到回复里给用户看。
- 阶段 4 先试点后批量；用户否定试点效果时回到阶段 3 改提示词或换生成方式，而不是盲目重跑。
- 如实说明能力边界：生成模型无法逐像素保留原片，V2V 保的是动作与构图的一致性；纯局部合成（只加一层火花不动原画面）优先评估 ffmpeg/剪辑手段。
- 分段生成总数 = 段数 + 每段至多 1-2 次返修；超出需先向用户说明并确认。
