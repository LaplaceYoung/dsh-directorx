# 单元化制作配方（默认叙事制作路径）

核心原则：**用户看得见、改得动每一个镜头**。所有生成先占位、成批确认、按镜头顺序执行；镜头之间用连续性契约衔接；与脚本设计逐镜对照。

适用：一切叙事成片任务（点子/剧本/小说出发）。

## DAG 知识（先验，不是执行脚本）
- idea2video：点子 → 故事 → 角色（+肖像）→ 剧本 → 分场景分镜 → 关键帧 → 镜头视频 → 成片
- script2video：剧本 → 角色（+肖像）→ 分镜 → 机位 → 关键帧 → 镜头视频 → 成片
- novel2movie（轻量）：小说 → 压缩 → 事件 → 场景 → 全局角色 → 分场景视频 → 成片
- novel2movie（重改编，默认）：小说 → **novel-adaptation 配方**（拆角色 → 大纲 → 美术 → 剧本，确定性质量门把关）→ script.json 交接本配方的分镜阶段

## 阶段序列

1. **析**（不生成）— 读全部输入材料（文本/上传文件），`view_image` 看参考图；回复中给出理解与缺口。
2. **问**（不生成）— `ask` 澄清：时长/画幅/平台/风格/必须保留的情节锚点。
3. **案**（不生成，LLM craft 可并行走 swarm）— 先 `skill_read` script-writing 与 storyboard-craft，把其 craft 要求写进给编剧/分镜任务的 brief；然后依次产出并逐步给用户确认：
   - 故事/脚本（文本）；
   - 角色表 + 外观契约（每角色一段可复用的形象描述块）；角色肖像用占位或经确认后定点生成；
   - **逐镜分镜表**：镜号 / 时长 / 景别 / 运镜 / 动作 / 光影措辞 / 声音点 / **continuity_in / continuity_out**（见契约）；
   - 全部写入 plan.md 并在回复中展示。
4. **位**（占位先行，不生成）— 分镜确认后，把**每一个**生成单元用 `mossland_prepare_generation` 排队：
   - `parameters.shot_idx` = 镜号（执行顺序）；
   - 按连续性契约填 `first_frame_path` / `last_frame_path` / `reference_image_paths`（会话相对路径，如 generated/frames/shot_01_last.png）；
   - prompt 自包含：主体+动作+运镜+光影+风格+时长全部写全；
   - 排队完毕后给用户**批次总览**（N 个单元、预计生成数、镜头链示意），由用户在生成面板点"全部确认并开始生成"。
5. **做**（用户确认后才发生）—
   - 批量执行由用户在面板启动（按 shot_idx 顺序）；agent 侧负责跟进状态、处理失败单元（改提示词后重新排队该单元，不整批重跑）；
   - 帧依赖的镜头（shot N+1 的 first_frame 依赖 shot N 的产物）在对应帧产出后再补齐其占位参数；
   - 用户明确要求 agent 直接执行时，先做 1 个试点镜头，验收后再继续。
6. **合**（不花生成预算）— `video_edit` / `ffmpeg` 按镜头顺序拼接，落实每镜声明的转场（默认硬切；叠化/划像用 xfade），配音/配乐/字幕，响度校准。
7. **验** — `video_understand` / `view_image` 自查成片：相邻镜头连续性、角色一致性、与脚本的时空一致性；给用户验收摘要（生成数 / 复用数 / 返修记录）。

## 镜头连续性契约（每个镜头必须声明衔接方式）
- **帧链接**（连续动作/空间）：上一镜的尾帧 = 下一镜的 `first_frame_path`；
- **参考锚定**（同场切换）：共享角色/风格 `reference_image_paths` + 逐字相同的光影措辞；
- **后期转场**（时空跳跃）：声明转场类型，assemble 阶段用 ffmpeg 落实。
- **双锚定是常态不是例外**：凡身份连续性要紧（帧链接或同场切换），master 参考图与链接帧**同时**携带——链接帧管时空，master 参考管身份。只吃生成帧的链只会单向漂移，不会自我纠正。
任何镜头缺 continuity 声明 = 分镜未完成。

## 长视频分段（镜头/单集超出可靠单段时长时）

开源社区的共识：单帧尾帧链接是最弱的衔接；接缝（可见跳变）和漂移（长链渐变）是两个问题，分开治。以下协议把两者都管住：

**计划**
- plan.md 列**分段清单**：每段 **4-6s**（甜点位，最长 ≤10s），每个接缝声明衔接方式——默认**首尾帧链接**；转场（硬切/叠化/划像）在计划里先声明，assemble 阶段落实。**转场是计划出来的，不是接缝处即兴补的。**
- **每 3-5 段规划一个收敛锚点**（分镜关键帧）：到达锚点的那段用**首尾帧双端锁定**（first+last frame）生成，把开环链变成闭环。链式生成约 5-6 跳后漂移肉眼可见——不带锚点的链不许跑过这个数。
- **重叠余量**：每段多生成约 0.5-1s 作为接缝工作区，合成时挑最优接缝点裁切。

**生成**
- **双锚定**：每个续段的占位参数同时带 `first_frame_path`（前段尾帧）和 `reference_image_paths`（master 参考，角色/场景/风格）。再锚定是每段的常驻条件，不是漂移后的补救。
- **尾帧挑选**：条件帧取段末附近的**最好一帧**，不盲目取最后一帧——生成器末几帧常有退化/向首帧回归；`view_image` 挑。
- **运动与相机状态要写进词里**：续段 prompt 写明延续中的动作（方向、速度），相机指令逐字复用；一段只给一个运镜。
- **逐段门禁**：每段完成后跑 `scripts/video/seam-check.sh <前段> <本段> chain`（接缝 PSNR/光照/运动三元组，基线相对判定），并 `view_image` 对 master 参考。**不过就返修该段，不带病往下链。**

**合成与核验**
- 按接缝清单裁切拼接；**运动镜头禁用 xfade 掩盖接缝**——xfade 是像素级过渡不感知运动，会出重影，它只用于声明过的切换点。
- 成片跑 `scripts/video/seam-check.sh --scan <成片>`：帧差离群帧 + 硬切兜底，**每个离群必须对应一个计划内转场**，对不上就是缺陷。
- 接缝断了回到对应分段返修（对锁定帧重生成那一段），不重 roll 整条。

**可引用产物规则**：任何会被后续单元引用的产物（锚定图、关键帧）必须在 `parameters.output_name` 声明裸文件名（如 `anchor_style.png`），执行时落盘为 `generated/<output_name>`；引用方一律写 `generated/<output_name>`。未声明 output_name 的产物文件名不可预测（shot_NN_<id>），禁止被引用。`shot_idx` 必须保证被引用者先执行。

## 门禁
- 阶段 1-4 零直接生成；全部单元占位完成前不得开始任何生成。
- 生成顺序 = shot_idx 顺序；失败单元单独重排，禁止整批重跑。
- 角色外观契约跨镜头逐字复用；光影措辞同场景内保持一致。
- 成片必须过自查才能交付；与脚本不符的段落回到分镜定位原因，而不是盲目重生成。
- 完成后把本流程的实战修正（踩坑/返修点）用 `playbook_write` 沉淀。
