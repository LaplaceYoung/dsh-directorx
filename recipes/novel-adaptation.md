# 小说改编配方（novel → 开拍素材 → 单元化制作）

适用：从小说/网文出发的短剧或叙事长片改编。产出四套结构化素材后，交接**单元化制作配方**完成分镜与生成。

核心原则：**确定性门禁先行**——每一层的 validate 是零成本脚本检查，必须跑过才进下一层；错误拦在写稿阶段，不流到生成环节（最贵的环节）才暴露。

## 四段接力（novel-* skills）

```
novel-characters → cast.json    （谁：画像 + 形象/音色提示词 + 设定图）
novel-outline    → outline.json （什么：改编说明 + 人物表 + 爽点表 + 分集梗概 + 资产清单）
novel-art        → art.json     （哪里 + 手里拿的：场景锚点 + 光照变体 + 叙事道具）
novel-script     → script.json  （戏：场次 + 节拍流 + 按角色聚合的台词本）
```

产物统一收在会话工作目录的 `novel/` 下。执行前 `skill_read` 对应 skill 全文，照它的步骤走。

## 阶段序列

1. **析**（不生成）— 读小说文本（pandoc/直接读），回复中给出理解：题材判断、体量（字数/章节数）、改编风险点。
2. **问**（不生成）— `ask` 一次问清：总集数 × 单集时长、题材、改编幅度（默认抽核）、目标平台、画风（realistic/ghibli，全程同档）。
3. **角色**（novel-characters）— cast.json。validate 必过。设定图**可选**：出图计划先给用户收敛（试点 1 张 → 确认后占位批量）。
4. **大纲**（novel-outline）— outline.json。吃 cast.json 当人物原料。**骨架拍板是硬门禁**：砍了哪条线、合了哪些人、大爆点落第几集，用户不点头不写分集。validate 13 道门必过。
5. **美术**（novel-art）— art.json。seed 吃 outline.json。画风必须与角色同档。validate 11 道门必过。设定图同样占位先行。
6. **剧本**（novel-script）— script.json。seed 吃 outline.json，validate 带 `--outline` `--art` 对账。**每批 ≤ 3 集**小批量出，时长预算（±15%）是硬门。
7. **交接** — 四份 JSON + 报告路径汇报给用户；确认后进入单元化制作的分镜阶段。

## 交接契约（novel/ → 单元化制作）

- **cast.json 形象提示词 → 角色外观契约**：逐字复用到每个镜头单元，不重写；角色设定图 → `reference_image_paths` 角色锚。
- **art.json 一致性锚点 + 光照变体 → 场景卡**：空景提示词生成场景参考图（同样占位先行）；同场景镜头的光影措辞从光照状态提示词逐字取用。
- **script.json 场次/节拍 → 分镜表输入**：Storyboard Artist 在场次/节拍之上加镜号、景别、运镜、continuity_in/out → storyboard.json。**时长预算是分镜的硬约束**：一集的镜头总时长必须落在 script.json 的目标秒数 ±15% 内。
- **台词本 → TTS**：按角色聚合的台词本直接喂配音批量生成；音频先行时它是 master clock 的稿源。
- **多集/长视频连续性**：集边界也是连续性契约——上一集结尾悬念接下一集开场钩子；跨集复用同一份外观契约与场景锚点，逐字引用不重写。单集分多段生成时，接缝一律按 unit-production 的长视频分段规矩走：默认首尾帧链接，转场在分镜计划里先声明，不即兴。
- 交接后按 unit-production 配方走：分镜确认 → 全部占位 → 用户面板执行 → 合 → 验。

## 门禁

- 每层 validate 不过不得进下一层；报错逐条修，改完重跑（零成本，不许跳过）。
- 骨架拍板（砍线/合人/爆点落位）未经用户确认，不得写分集梗概。
- 一切出图占位先行：试点验收 → 批量占位 → 用户在生成面板执行；禁止未确认批量出图。
- 角色与美术的画风必须同档；跨层引用（场景/角色/道具/光照状态）由 validate 对账，不靠记忆。
- 体检模式：用户拿现成大纲来，只跑 novel-outline 的 checkup 给诊断，不擅自重写。
- 改稿联动：用户改了上游（合人/砍场景/挪爆点），重跑下游 validate，按报错点名修复断裂引用。
