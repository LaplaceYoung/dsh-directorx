# 知识库治理

`knowledge/` 采用“正文 Markdown + 侧车元数据”的结构，避免给 389 篇正文批量插入 frontmatter 造成无意义的大范围改动。

## 文件职责

- `taxonomy.json`：编号段与分类名称的唯一来源。
- `redirects.json`：被去重合并的旧编号到规范文章的映射。
- `inventory.json`：由扫描脚本生成的机器可读清单。
- `audit-report.md`：由扫描脚本生成的质量与重叠候选报告。
- `../INDEX.md`：由扫描脚本按数字顺序生成的人工导航索引。

## 维护命令

```bash
npm run knowledge:audit
npm run knowledge:check
```

`knowledge:audit` 会重新生成索引、清单和审计报告。`knowledge:check` 不写文件，在生成结果与仓库内容不一致、存在无法解释的编号缺口、重定向失效或结构错误时返回非零退出码。

## 清洗原则

1. 编号是稳定标识，不因标题优化而重排。
2. 明确重复的文章先合并，再在 `redirects.json` 保留旧编号。
3. 相似度报告只表示“需要人工复核”，不能作为自动删除依据。
4. 模型、平台、法规和年份相关内容需要定期复核；自动扫描不替代来源核验。
5. 正文保留来源与业务上下文，索引只承担导航，不复制全文摘要。
