# 直播与实时制作（Live Production）

> 本页是 DirectorX 直播知识库：直播制作岗位与流程、多机位切换逻辑、推流编码最佳设置（OBS 2026）、延迟类型、直播灯光与收音、直播电商 SOP。每个概念含参数与检查清单。
> 来源：Dacast OBS 设置指南 2026、YouTube Live 编码规范、Videomaker 多机位指南（索引）、Godox 直播灯光方案、行业直播电商 SOP。

## 概述

直播制作（Live Production）与录制的本质区别：**没有重来的机会**——错误直接播出。因此直播的核心是**流程纪律**：预先设置、分工明确、切换逻辑清晰、冗余备份（备份机位/备份网络/备份供电）。

**关键认知**（Dacast）：推流设置不是平台合规问题，而是**交付架构问题**——编码器输出决定下游所有环节（CDN 缓冲、ABR 阶梯、播放器体验）。CBR + 2 秒关键帧是直播稳定的基石。

## 直播制作岗位与流程

### 岗位分工（小团队可合并）
| 岗位 | 职责 |
|---|---|
| 导演 Director | 切换决策（看哪个机位）、节奏把控 |
| 技术导演 TD | 操作切换台/导播软件，执行导演指令 |
| 摄像 Camera Operator | 各机位构图与跟随 |
| 音频 Audio | 混音、电平监控 |
| 推流/编码 Encoder Op | 监控推流状态、网络、丢帧 |
| 场控/主持 Flow Host | 流程推进、观众互动 |
| 灯光/场务 | 布光维持、现场问题 |

### 开播前检查清单（Pre-Show Checklist）
```
□ 网络测速（上传 ≥ 推流码率 1.3 倍，留 20-30% 余量）
□ 各机位构图/白平衡/对焦确认
□ 音频电平（人声 -12~-6dBFS，无爆音）
□ 灯光全开检查（无频闪/色温一致）
□ 推流设置核对（CBR/码率/关键帧 2s/分辨率/帧率）
□ 备份：备用网络（4G/5G）、备用电源、备用推流（本机录制）
□ 测试信号推流 30 秒验证
□ 台本/提词/流程表在手
□ 时间码/时钟统一
```

## 多机位切换逻辑（Multi-Camera Switching）

### 标准配置
- 主机位（全景/主景）+ 特写机 + 移动机（游机）+ 备用机。
- 导播原则：**切换要"有理由"**——谁在说话切谁、重点在哪儿切哪儿；不切则留主景。
- **切换节奏**：访谈每 10-30 秒切一次；带货演示跟随产品/动作切换；对话用正反打逻辑（呼应 01 文档 shot/reverse shot）。

### 切换类型
| 切换 | 定义 | 用途 |
|---|---|---|
| 硬切 Cut | 瞬时切换 | 默认，节奏最快 |
| 叠化 Dissolve | 短暂叠画 | 舒缓、时间推移 |
| 白闪/黑闪 | 闪白闪黑 | 段落间隔、开场收尾 |
| 画中画 PIP | 主画面+小窗 | 演示+主持人同屏 |

### 切换纪律
- **切换前先"看"**：TD 需在切换前预监（Preview）目标机位——确认构图/对焦再切（"先预监后切"铁律）。
- 机位运动时不切（推拉摇进行中切换易晕）——等运动到位。
- 声音跟随画面：切谁给谁的声音（自动混音或手动跟随）。

## 推流编码最佳设置（OBS 2026，Dacast 官方）

### 黄金三原则（理解后适用于任何平台）
1. **CBR（恒定码率）**：直播永远用 CBR，不用 VBR——VBR 的码率尖峰超出缓冲区导致丢帧/断流。
2. **关键帧间隔 2 秒**：HLS 分段（2-6 秒）必须以关键帧开头；2 秒关键帧兼容所有常见分段，保证 ABR 切换顺畅。**不要留 auto**。
3. **总码率 ≤ 实测上传的 70-80%**：留出抖动余量，避免长直播掉帧。

### 推荐预设（按分辨率）
| 场景 | 分辨率/帧率 | 视频码率 | 音频 |
|---|---|---|---|
| 通用专业直播 | 1080p/30 | 4,500-6,000 Kbps | AAC 160 Kbps 48kHz |
| 高动态（体育/游戏） | 1080p/60 | 6,000-9,000 Kbps | AAC 160-320 Kbps |
| 低配电脑/低上行 | 720p/30 | 2,500-3,500 Kbps | AAC 128-160 Kbps |

### 编码器选择
- **优先硬件编码**（NVENC/AMD AMF/Intel QSV/Apple VideoToolbox）：直播是持续负载，CPU 软编（x264）长时间高复杂度场景会劣化。
- 编码格式：H.264 通用（RTMP 全兼容）；AV1/HEVC 需平台 Enhanced RTMP 支持，未确认不用。

### 平台上限速查
| 平台 | 1080p 安全码率 | 关键帧 | 备注 |
|---|---|---|---|
| Twitch | ~6,000 Kbps | 2s | 严格封顶，留 10% 余量 |
| YouTube Live | 4,500-9,000 Kbps | 2s | 容忍更高码率 |
| Facebook Live | 4,500-9,000 Kbps | 2s | 1080p/30 为实用上限 |
| 专业 CDN（Dacast 类） | 4,500-6,000 Kbps | 2s | 决定 ABR 最高档位 |

### 关键架构认知
- **推流码率 = ABR 天花板**：推 3,000 Kbps 则最高档约 720p——想要观众看到 1080p，推流必须 4,500+ Kbps。
- **掉帧处理**：先降分辨率（720p），再降码率，最后降帧率——按这个顺序。

## 延迟类型（Latency）

| 类型 | 延迟 | 适用 |
|---|---|---|
| 标准延迟 | 15-30s+ | 大活动、安全要求高 |
| 低延迟 | 3-8s | 常规互动直播 |
| 超低延迟（WebRTC/WHIP） | <1s | 付费互动、远程制作、教学 |
| 实时（SRT 专线） | <500ms | 专业制作回传 |

**选择**：互动型直播用低延迟；需要"先审后播"（合规）用标准延迟；远程嘉宾用 WebRTC/NDI。

## 直播灯光与收音

### 灯光（直播间）
- **三点布光基础**（见 09 文档）+ 直播特化：
  - 主光：柔光箱 45°，色温统一（3200K/5600K 二选一）；
  - 轮廓光：背后侧光把主播从背景分离；
  - 背景光：打亮背景层次（品牌墙/产品架）；
  - 眼神光：主播眼睛里的光点（环形灯/小面灯）。
- **产品区独立补光**：带货直播产品需要单独灯光（顶光+侧光，消除反光）。
- **色温一致性**：所有灯同色温，避免脸黄背景蓝。

### 收音（直播间）
- 主麦：领夹/无线（干净、贴身）或心形电容麦（桌面）——优先领夹（手部动作自由）。
- 备份麦：第二个麦同步录音（保险）。
- 电平：人声 -12~-6dBFS；音乐/音效低于人声（呼应 06 文档）。
- 房间：吸音处理（毯子/隔音棉）、关空调冰箱。

## 直播电商 SOP（前中后）

### 直播前（Pre-Live）
- 选品与台本：每个品的"卖点-演示-逼单"话术卡；
- 设备检查（见开播检查清单）；
- 预热：短视频预告、社群通知、预约功能；
- 福利设置：优惠券/秒杀/抽奖规则确定。

### 直播中（Live）
- 开场钩子：前 5 分钟留人（福利预告/悬念）；
- 节奏：每 15-30 分钟一个福利节点；讲解-演示-逼单循环；
- 互动：读评论、回答问题、点名感谢；
- 数据监控：在线人数、点击率、转化——及时调整讲解重点；
- 配合：助播递品/补话术/盯后台。

### 直播后（Post-Live）
- 复盘：在线峰值、停留时长、点击转化、成交额（呼应 16 文档复盘表）；
- 内容复用：直播切片剪成短视频（二次分发）；
- 私域沉淀：粉丝群/复购运营。

## 在 AI 视频生成中的应用

1. **直播切片**：AI 从直播录屏自动切高光（讲卖点/互动/演示片段）→ 竖屏短视频（见 05 文档模式）。
2. **预告片**：AI 生成直播预告（产品+时间+福利），统一视觉风格。
3. **数字人直播**：AI 数字人 24 小时直播（话术循环）——注意平台合规标注；真人直播的信任感仍不可替代。
4. **字幕实时化**：AI 实时字幕（口播转文字）提升留存与无障碍。
5. **复盘自动化**：AI 总结直播数据与话术命中率，输出改进建议。

## 常见错误

1. 用 VBR 推流：码率尖峰 → 丢帧断流。
2. 关键帧留 auto：ABR 切换卡顿。
3. 码率超过上传带宽：长直播必断。
4. 切换不预监：切到没对焦/没构图的机位。
5. 机位运动时切换：观众眩晕。
6. 无备份网络/电源：播到一半断流。
7. 直播灯光色温混用：脸黄背景蓝。
8. 只靠机身麦：声音差，观众秒退。
9. 开播前不测流：正式推流才发现设置错误。
