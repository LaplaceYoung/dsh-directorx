# 九、节奏与输出层（补充）

## 24. 音频设计 [L1 L2 L3]

**作用**：控制音画关系。对音乐驱动型视频（预告片、动作片、产品片），音频踩点是核心技能，不是附属品。

**为什么独立成章**：很多 skill 把音频塞进"基础信息"一行草草了事。但案例1（动作预告片）的灵魂恰恰在音频——`accent hit on each leap`（每次跳跃一记重击）、`the score bursting at 4s`（4秒配乐爆发）。音频与画面是平等的双轨道设计。

**填写要点**：
- **分层声明**：环境音（room tone/风/雨）/ 拟音（脚步/机械/衣物）/ 配乐（低频/旋律/鼓点）
- **踩点锚定**：声明关键动作落在哪个音乐重音上（"每次跳跃对齐一记重击"）
- **时间锚点**：标注配乐的爆发/收束时间点（"4秒配乐爆发，收束最后1秒"）
- **L1 用一句话串联**；L2/L3 用时间轴

**好的示例**（L1，来自案例1）：
> Audio: wind, rapid footsteps, city ambience, low score underneath, an accent hit on each leap, the score bursting at 4s, closing the last 1s.

**好的示例**（L2/L3，来自案例4产品片）：
> Audio: deep pulsing sub-bass room tone, sharp tactile mechanical clicks, a sweeping glassy whoosh on cuts, and a rising electronic swell that resolves to near-silence on the final fade.

**坏的示例**（太笼统）：
> Audio: background music and sound effects.

**关于"无音乐"**：如果视频确实不要配乐，必须显式声明"音乐状态：无"——否则 AI 可能自作主张加 BGM。参考案例3基础信息写法。

# 十、转场与节奏层（新增）

## 25. 转场机制 [L2 L3]

**作用**：控制镜头间的过渡方式。L2 相比 L1 的最大增值就在这里。

**核心区分——两种转场**：
- **孤立转场**（L1级）：每个镜头末尾写一句"切到下一镜头"。简单有效，但镜头间无内在联系。
- **变形链转场**（L2/L3级）：前一个镜头中的某个图形元素**自然变形**为后一个镜头的主体结构，形成贯穿全片的视觉连续性。这是参考提示词B的招牌竞争力。

**转场类型清单**（按风格选用）：
| 类型 | 适用风格 | 说明 |
|---|---|---|
| 图形匹配变形 | MG/二维 | 刀刃→圆环→月相→蝴蝶→瞳孔，元素自然演化 |
| 杂志翻页/纸张折叠 | Editorial MG | 页面物理翻转露出新内容 |
| 黑白反相 | MG/风格化 | 正负形瞬间替换 |
| 正负形替换 | MG/海报 | 图底关系翻转 |
| 印刷套色错位 | MG/印刷感 | CMYK错位产生动感 |
| 斜向遮罩/刀刃形色块 | MG/锐利风 | 几何切片划过 |
| 剪影匹配 | 任意 | 前镜剪影轮廓=后镜主体轮廓 |
| 匹配剪辑（图形匹配的写实版） | 写实 | 前镜全屏元素=后镜首帧主体（如猩红圆点→酒杯液面） |
| 硬切 | 任意 | 干净利落，踩音乐节拍 |
| **禁止**：普通淡入淡出 | — | 廉价感 |
| **禁止**：无意义闪白/连续闪白 | — | 干扰 |
| **禁止**：柔和溶解 | — | 软弱 |

**设计变形链的操作步骤**（L2/L3 关键技巧）：
1. **先定 3-6 个核心视觉母题**（如刀刃、圆环、月相、蝴蝶、瞳孔、纸张）
2. **画出母题在镜头间的变形路径图**（母题A → 变形为 → 母题B → 变形为 → 母题C）
3. **每个镜头末尾声明**："本镜的 {X元素} 变形为下一镜的 {Y结构}"

**好的示例**（变形链，来自案例2）：
> 刀尖横向划过页面，留下青蓝与黑色双层印刷轨迹……最终裂成一道由右下延伸至左上的斜向裁纸刀切口。切口快速二维放大并覆盖全屏，完成第一组匹配转场。

**坏的示例**（孤立转场，无变形逻辑）：
> 镜头一切，画面变成下一个场景。

## 26. 错峰时序控制 [L2 L3]

**作用**：防止"所有元素同时运动"导致的画面崩塌。这是 SKILL.md 设计原则第3条，但之前缺少操作指引。

**定义**：同一事件（冲击/入场/退场）触发的多个视觉元素，按 2-3 个层级、间隔 2-3 帧**依次**出现/退出，禁止同时运动。

**填写模板**：
```
第X拍触发：
  第一层 {元素A（如极细横线、裁切符号）}
  → 间隔 2-3 帧 →
  第二层 {元素B（如时钟刻度、数字标记）}
  → 间隔 2-3 帧 →
  第三层 {元素C（如青蓝矩形、断裂圆环碎片）}
```

**适用时机**：
- **冲击瞬间**（落脚/挥刀/爆发）：元素向画面边缘弹开
- **元素入场**（新视觉元素出现）：分层级生长/滑入
- **高潮退场**（结尾收束）：分层级消失（先消失次要，再收拢主体）
- **标题拼装**（落版）：字母由不同元素逐层拼成

**好的示例**（来自案例2）：
> 冲击元素分三个层级错峰出现：第一层为极细横线和裁切符号，第二层为时钟刻度与不可辨识的数字标记，第三层为青蓝矩形和断裂圆环碎片，各层间隔两至三帧依次向画面边缘弹开。

**坏的示例**（所有元素同时出现）：
> 落脚瞬间，横线、刻度、矩形、圆环同时闪现。

**数值灵活化**：层级数（2-3层）和帧间隔（2-3帧）是参考默认值，不是硬约束。快节奏可2层间隔2帧，史诗节奏可3层间隔4-6帧。

## 27. 段间衔接锚点 [L2 L3]

**作用**：AI 视频是**逐段生成**的（受限于单次生成时长）。多段视频的首尾必须能拼接，否则段间断层。这是 skill 初版完全遗漏的关键技巧。

**核心原则**：**前段最后一帧的全屏元素 = 后段第一帧的主体**（匹配剪辑思维）。

**强制约束**：
- 前段结尾静止 6-8 帧，作为"锚点定格"（让 AI 有稳定的结束帧）
- 后段开头声明"承接上一段结尾的 {具体元素}"
- 禁止段间用淡入淡出/黑场/标题卡衔接（除非刻意设计）

**好的示例**（来自案例2段间衔接）：
- 第一段结尾：`猩红圆点保持完整平面正圆形，以画面中心为轴快速二维放大，圆形边缘越过画面四周并覆盖全屏，直接匹配为酒杯内部的猩红色液面极近特写……保持绝对静止6至8帧。第一段在此结束，画面必须固定为纯粹的猩红酒液拼接锚点，用于无缝连接第二段开头。`
- 第二段开头：`承接上一段结尾，全屏为酒杯内部的猩红色液面极近特写……`

**多段资产共享规则**：
- 角色/场景资产锁定模块在所有段共享（复制到每段提示词）
- 叙事因果链必须延续（第一段的胜负/状态影响第二段）
- 视觉状态衔接（第一段结尾火焰覆盖→第二段开头火焰显脸）
- 每段可有独立增强模块（如第二段独有变身逻辑）

**何时需要此模块**：视频超过单次生成上限（主流平台 5-16 秒，见下表）时，必须拆多段并设计衔接锚点。在 SKILL.md 第一步收集参数时，已收集"段数/在作品中的位置"。

### 主流 AI 视频平台单次生成时长上限（2026年8月调研）

| 平台 | 单次原生上限 | 扩展上限 | 备注 |
|---|---|---|---|
| **Kling / 可灵** | Standard 10秒 / Pro 5秒 / Narrative 15秒 | 约3分钟（每次延4-5秒） | 6-8秒是质量甜区；支持 `{{Mixed N}}` 多图 |
| **Sora 2 / 2-pro** | 4/8/12秒（标准）/ 16-20秒（Pro）/ 最高25秒 | 约120秒（最多延6次） | 各档位按订阅等级浮动；英文响应更好 |
| **Runway Gen-4 / 4.5** | 5或10秒（原生） | 60秒（Extend功能） | Turbo版更快；基于图+文生成 |
| **Vidu (1.5 Pro)** | 10-16秒/段 | — | 1080p，每段2-5分钟生成 |

**判断规则**：
- 用户时长 ≤ 目标平台原生上限 → **单段**，无需衔接锚点
- 用户时长 > 目标平台原生上限 → **必须分段**，按下述策略拆分
- 用户未指定平台 → 按"主流单次上限约10秒"保守判断

### 分段策略推荐（按时长 + 平台）

分段的目标是"每段落在平台单次上限内 + 段间能无缝拼接"。推荐策略：

| 目标总时长 | 目标平台 | 推荐分段 | 单段时长 | 衔接方式 |
|---|---|---|---|---|
| ≤10秒 | 任意 | **单段** | 全长 | 不需要 |
| 15-20秒 | Kling(S) / Runway / Vidu | **2段** | 各8-10秒 | 段间衔接锚点（#27） |
| 15-20秒 | Kling(Narrative) / Sora(Pro) | **单段**（若≤15/20秒） | 全长 | 不需要 |
| 25-30秒 | 任意 | **3段** | 各8-10秒 | 两处衔接锚点 |
| 45-60秒 | 任意 | **4-6段** | 各8-10秒 | 多处衔接锚点；考虑用 Extend 功能链式延长（Kling/Runway支持） |
| 60秒+ | 任意 | **6段+** | 各8-10秒 | 必须用平台 Extend 功能 + 每段衔接锚点 |

**分段三原则**：
1. **按叙事段落切，不按等时长切**：在场景转换/情绪转折处分段，衔接更自然（如案例2在"猩红圆点→酒杯液面"转场处分段）
2. **每段独立完整**：每段提示词都包含完整的角色/场景资产锁定（复制到每段），可独立生成
3. **段长可不等**：高潮段可短（5-8秒，信息密集），铺垫段可长（10-12秒）。无需强制等长

**分段时的字数口径**：每个等级的字数参考（L1~300字/L2~2000字/L3~5000字）均按**单段**计。多段作品总字数 = 单段字数 × 段数。

**与 Extend 功能的区别**：平台的 Extend 是"AI 自动延续上一段"，衔接由平台处理，但叙事不可控；本 skill 的衔接锚点是"手动设计首尾匹配剪辑"，叙事完全可控但需手写。**高质量作品优先用衔接锚点，快速出长片可用 Extend**。

# 十一、特效与状态层（新增，L3 核心）

## 28. 特效行为规则 [L3]

**作用**：控制特效（火焰/能量/光芒/魔法）本身的**运动行为和物理规则**。这是写实格斗/奇幻戏的核心模块，初版完全遗漏。

**为什么独立于色卡和光影**：
- 色卡模块管"特效是什么颜色"
- 光影模块管"特效如何照亮场景"
- 本模块管"特效怎么运动、怎么生长、怎么释放"——三者正交，缺一不可。

**填写字段**：
1. **触发源**：特效从哪里开始（如"火焰从右手自然燃起，先在指缝、掌心出现"）
2. **蔓延/演化时序**：按顺序列出蔓延路径（"沿右手→前臂→肩膀→胸口→后背→腰部→双腿"）
3. **分层结构**：内层/中层/外层各是什么（见下方火焰分层示例）
4. **释放动作发力链**：特效爆发时的身体发力（"前脚踩死→腰胯拧转→右肩带动右臂斜向挥出→手腕末端甩开"）
5. **吞没边界**：特效可以覆盖什么、不可以覆盖什么（"火焰可覆盖前方和街道深处，但草薙京的头部轮廓、脸部、肩线、白夹克边缘必须清晰可见"）

**火焰分层结构范例**（来自案例3，可复用）：
```
内层：贴附身体表面的液态火焰，像熔金火液沿肌肉线条滑动
中层：翻涌火浪
外层：高热气流、透明热浪、火星粒子、深红烟尘
```

**"小太阳"概念澄清**（常见误解）：
> "小太阳"指人形高能火焰状态的亮度、热量、密度和太阳表面般液态等离子翻涌质感，**不是球形太阳，不是能量球**。

**释放动作的"不是X而是Y"**：
- **不是**掌心喷射、火柱、原地爆炸、身体周围炸一圈
- **而是**沿右臂挥动轨迹被甩成扇形火幕，贴着街道纵深向前铺开

**吞没边界原则**：特效要"大量包裹但不能吞没人形主体"——头部轮廓、脸部、肩线、关键动作、服装边缘必须清晰可见。这是防止特效喧宾夺主的关键纪律。

## 29. 角色状态转换 / 变身链条 [L3]

**作用**：控制角色的觉醒/变身/形态切换。对奇幻/超能力/格斗戏是核心模块，初版完全遗漏。

**为什么独立**：变身是高崩坏风险节点——AI 最容易在这里"直接跳切"或"一键替换模型"。需要独立的链条约束。

**完整状态链模板**（用箭头串起，禁止跳切）：
```
{初始状态} → {起势} → {蓄力} → {过渡材质变化} → {新形态识别点} → {展开} → {最终状态}
```

**范例**（来自案例3大蛇觉醒）：
```
站立 → 起势（肩背下沉、重心下压）→ 下蹲蓄力（标志姿势）→ 液态上流（衣物/头发/身体表层反重力上升）→ 低伏抬头完成大蛇化（关键识别点）→ 站起 → 低空半漂浮
```

**每步的物理过渡方式**（必须声明，不能省略）：
- 起势：肩背向下压，头部微低，双臂向身体内侧收拢
- 蓄力：身体缩成紧凑一团，一侧膝盖前顶，双臂交叠抱压
- 过渡材质变化：**声明材质是什么**（见下方"过渡材质正负面约束"）
- 新形态识别点：通过某个明确动作（如"抬头"）完成形态切换的视觉确认

**过渡材质的正/负面约束**（防崩坏关键）：

✅ **正面允许**（选其一作为过渡材质）：
- 干净、连续、丝带状的上行流体光带（反重力能量转译）
- 粒子化光尘
- 能量纹路重组

❌ **负面禁止**：
- 融化（像蜡融）
- 黏液（恶心感）
- 腐烂（恐怖感）
- 破碎（像玻璃碎）
- 烟化（像烟雾消散）

**好的示例**：
> 液态化不是融化、黏液、腐烂、破碎或烟化，而是衣物、头发和身体表层被反重力能量转译为干净、连续、丝带状的上行流体光带，材质高级、克制、无恐怖感。

**空间连续性约束**：变身必须在**同一空间轴线**上连续完成，不能位移（站立起势的位置 = 后续下蹲 = 变身 = 站起漂浮的位置）。

**最终形态的姿态锁定**（如有标志性姿势）：
- 声明手势（如"双手在头顶上方交叉成X型"）
- 声明漂浮高度（如"低空半漂浮，双脚仅离地一小段克制高度"）
- 声明身体细节（如"胸腔打开，头部微微自然后仰"）

# 十二、标记与工具库（补充）

## 30. `{{Mixed N}}` 多角色参考图标记系统 [L3]

**作用**：在多角色写实 CG 中，为每个角色/场景锁定独立的参考图，保证一致性。

**`{{Mixed N}}` 是什么**：
这是多参考图融合标记，N 是编号槽位。在支持多图输入的 AI 平台（如 Kling、可灵、即梦等）中，每个 `{{Mixed N}}` 对应一张上传的参考图。提示词中出现 `{{Mixed 1}}` 的地方，就会应用第1张参考图的特征。

**编号分配规则**（推荐惯例）：
| 标记 | 通常分配给 | 说明 |
|---|---|---|
| `{{Mixed 1}}` | 主角 A | 第一主角，出场最多 |
| `{{Mixed 2}}` | 主角 B / 对手 | 第二角色 |
| `{{Mixed 3}}` | 场景 | 环境参考图 |
| `{{Mixed 4}}` | 主角的变身/第二形态 | **为什么单独占槽位**：因为参考图不同，变身后的形态需要独立的图来锁定 |
| `{{Mixed 5+}}` | 道具/次要角色 | 按需 |

**为什么变身角色要单独编号**：变身前后是两个不同的视觉形态，需要两张不同的参考图。如果共用一个编号，AI 会混淆。

**使用示例**（来自案例3）：
```
草薙京 {{Mixed 1}}：冷峻青年格斗者，深棕黑蓬松分层短发……
克里斯 {{Mixed 2}}：红衣少年格斗者，浅棕蓬松短发……
香港九龙红霓虹旧街格斗区 {{Mixed 3}}：严格参考香港九龙资产图……
大蛇 {{Mixed 4}}：人形神性压迫形态，银白凌乱短中发……（变身后的形态）
```

**单参考图时**：如果只有一个角色，仍建议用 `{{Mixed 1}}` 标记，便于平台识别。也可以省略标记，直接描述。

**各平台操作对应**：
- **Kling/可灵**：在"角色"上传 N 张图，提示词中用 `{{Mixed N}}` 引用
- **即梦/其他**：参考各自的多图输入文档；标记语法可能不同，但"编号对应上传顺序"的逻辑通用

## 31. "不是X，而是Y" 纠正句式对照库 [L2 L3]

**作用**：这是纠正 AI 已知错误最有效的句式。初版只给了4个范例，此处系统化扩充为按类别组织的对照库。

**使用方法**：组装提示词时，扫描下表，如果你的场景命中某类 AI 易错点，把对应的纠正句式写进提示词（动作逻辑模块、特效行为模块、或严格禁止模块）。

### 动作类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 打空后主动收拳（像表演） | "右拳打空后**不是**主动收拳，**而是**顺着出拳惯性继续走完轨迹，再借身体旋转自然带回" |
| 站稳再攻击（割裂节奏） | "每个动作结束时身体**已进入**下一动作准备状态，**不能**重新站稳再攻击" |
| 远程对轰（该近战时） | "**不是**远程释放火球，**而是**右拳包裹高热火焰贴身近战火拳攻击" |
| 后拉被理解成逃跑 | "后拉**不是**逃跑，**而是**打空后的余势回带与蓄力前的拉位动作" |
| 飞踢为了命中 | "飞踢**不是为了**命中，**而是为了**高速压近距离" |
| 站桩/僵住 | "克里斯**不能**站桩，始终保持动态格斗姿态" |
| 只动头不动身体 | "躲闪时头部、颈部、肩膀、胸腔、腰部形成**连续**后撤弧线" |

### 特效类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 火焰像水流胶体 | "液态火焰**不是**水流胶体，**而是**贴附身体表面的熔金火液" |
| 小太阳变成球体 | "'小太阳'**指**人形高能火焰状态的亮度热量密度，**不是**球形太阳，**不是**能量球" |
| 释放变掌心喷射 | "释放**不是**掌心喷射、火柱、原地爆炸，**而是**沿挥动轨迹甩成扇形火幕向前铺开" |
| 火焰吞没人形 | "火焰大量包裹全身**但**头部轮廓、脸部、肩线、白夹克边缘必须清晰可见，**不能**完全糊成一团火" |
| 火焰无层次 | "火焰必须分层：内层X / 中层Y / 外层Z" |

### 状态/变身类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 直接跳切成新形态 | "**不能**直接从站姿跳切成大蛇，**不能**从头到脚一键替换式变身" |
| 变身材质恐怖化 | "液态化**不是**融化、黏液、腐烂、破碎、烟化，**而是**干净连续丝带状上行流体光带" |
| 变身时位移 | "变身必须在**同一空间轴线**上连续完成，**不能**位移" |

### 光影/特效质感类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 终极光效变圣光 | "最终光线**不能**柔和、温润、圣洁、治愈、圣光感，**必须**凌厉、锋利、具攻击性和切割感" |
| 出现明确发光点 | "观众**看不到**明确发光点、光球、圆盘光源、灯泡感亮点，**只能**看到从轮廓后方迸发的逆光边缘" |
| 格挡变实体墙 | "格挡**不**出现具现化墙面、护盾面、玻璃罩，**只能**表现为前方空间本身突然凝滞" |
| 柔和泛光 | "逆光**不是**柔雾状均匀泛光，**而是**硬边轮廓、锐利光束、切割感光刃" |

### 空间/镜头类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 反打当新动作 | "反打视角中同一飞踢向右擦过，这是**同一运动轨迹**的反向观察，**不是**新动作" |
| 跨镜头跳轴 | "**不能**左右互换、**不能**方向反转" |
| 镜头内乱切机位 | "每个镜头**只完成**指定动作，**禁止**单镜头内自动乱切机位" |

### 转场类

| AI 典型错误 | 纠正句式模板 |
|---|---|
| 用淡入淡出 | "**不使用**普通淡入淡出和无意义闪白" |
| 转场无变形逻辑 | "前一个镜头中的图形元素**必须自然变形**为后一个镜头的主体结构" |

## 32. 参考图生视频（image-to-video）范式 [L1 L2 L3]

**作用**：当用户有参考图（产品图/角色立绘/场景概念图）时，提示词的写法与纯文生视频**本质不同**。本章节定义图生视频的"留白原则"。

**核心洞察——参考图已经锁定了什么**：
有参考图时，主体的**静态外观**（形状、颜色、材质、构图、比例）已经被图锁定了。提示词如果再详细重复描述这些，反而会与参考图"打架"，导致 AI 困惑或过度变形。提示词的价值转移到参考图**无法表达**的东西上。

### 留白原则：图生视频时该写什么、不该写什么

| 维度 | 参考图已锁定 → 提示词该留白 | 参考图无法表达 → 提示词必须写 |
|---|---|---|
| 主体外观 | ❌ 形状、颜色、材质的静态描述（图里已经有了） | ✅ 材质在不同光影下的**动态表现**（折射/反射/高光流动） |
| 构图 | ❌ 主体在画面中的位置（首帧就是图） | ✅ 主体如何**离开**初始构图（漂浮/旋转/运镜推拉） |
| 环境 | ⚠️ 仅当图里有环境时留白；图是纯背景则需写 | ✅ 环境的**恒定性声明**（防漂移）+ 环境对动作的**响应** |
| 时间 | ❌（静态图无时间） | ✅ **运镜动词**（push-in/glide/orbit/sweep）+ 时间线 |
| 光影 | ⚠️ 图里的基础光照可留白 | ✅ 光影的**变化**（脉动/扫描/渐强/收束）+ 光与材质的**互动** |
| 音频 | ❌（图无声） | ✅ 完整音频设计（参考 #24） |
| 材质母题 | ❌（图已显示材质） | ✅ 材质母题的**反复表现指令**（"所有镜头围绕此材质特征"） |

### 图生视频提示词的四大特征（从案例4提炼）

**特征0：首帧锚定（图生视频第一命门）**

图生视频的存在意义就是"让参考图动起来"。如果视频首帧与参考图不一致，整个产品就废了。因此**首帧锚定是图生视频的第一原则**，必须用**正面陈述**写进 Shot 1 的开头（不是放进负面约束的禁止项）。

```
SHOT 1: The scene opens exactly on image 1, ...
```
- 用 `opens exactly on image 1` / `the scene opens on the reference` 这种**正面肯定句**作为视频起手式
- **不要**写成 "do not deviate from image 1" 这种弱否定——正面陈述对 AI 的约束力远强于否定
- 首帧 = 参考图，后续镜头才允许运镜/变化

**特征1：参考图锚定 + 环境恒定声明**
```
The transparent gaming mouse from <Picture 1> in its original scene:
... The environment is constant throughout.
```
- 用 `from <Picture N>` / `{{Mixed N}}` 指明参考图来源
- 用 `in its original scene` 声明"保持图里的环境"
- 用 `The environment is constant throughout` 一句话**禁止环境漂移**（这是图生视频最重要的防崩坏声明——AI 容易在多镜头间偷偷换背景）

**特征2：材质母题（Material motif）作为全片线索**
```
Material motif: glowing internal metallic micro-components and glossy acrylic refractions.
```
- 参考图已显示材质，但提示词要**点名**哪个材质特征是全片核心
- 这相当于 L2"视觉母题变形链"在写实产品片中的等价物

**材质母题的差异化表现（核心节奏）**：每个镜头应从**不同物理维度**差异化揭示同一材质母题，禁止多个镜头用同一机位距离重复表现。参考案例4的三镜头节奏：

| 镜头 | 攻击的物理维度 | 运镜 | 光影互动 |
|---|---|---|---|
| Shot 1 | **内部结构**（电路/微组件） | push-in（深入） | refracting through the shell |
| Shot 2 | **表面纹理**（滚轮/金属扫光） | glides along the side（横扫） | sweeps across metallic textures |
| Shot 3 | **边缘折射 + 整体轮廓** | rotating in orbit（环绕） | flares along the glassy edges |

可选的差异化维度清单：内部结构 / 表面纹理 / 边缘折射 / 整体轮廓 / 动态形变。

**特征3：每镜头 = 机位 + 运镜动词 + 光影互动**
```
SHOT 2: ... extreme macro profile ... the camera glides slowly along the side
as a sharp beam of warm orange light sweeps across the metallic textures,
contrasting perfectly against the deep blue ambient glow.
```
- 图生视频的镜头描述**重心在运镜和光影**，不在主体外观
- 必须有明确的**运镜动词**（见下方动词库）
- 必须声明**光如何与材质互动**（refracting through / sweeping across / flares along edges）

**图生视频运镜动词库**（按功能分类，产品片/概念片高频）：

| 功能 | 运镜动词 | 适用 |
|---|---|---|
| 揭示内部 | push-in / macro dive / deliberate push-in | 显电路、内部结构、深度 |
| 扫过表面 | glides along / sweeps across / tracks along | 显纹理、材质扫光、侧面细节 |
| 展示全貌 | rotating in orbit / slow orbit / full reveal | 环绕展示、360°呈现 |
| 主体位姿变化 | levitates / rises / rotates / weightless drift | 悬浮、脱离表面、旋转 |
| 收束/落幕 | fade to silhouette / pull-back / resolve to still | 收尾、剪影化、归于静止 |
| 光影动作（配合运镜） | pulse brighter / sweep across / flare along / refract through | 光的脉动、扫描、折射 |

### 图生视频 vs 文生视频的模板差异

图生视频时按等级选用对应差异表。**L1 图生视频最常见**（产品片大多是 L1），所以先给 L1 表。

#### L1 图生视频差异表（适用案例4这类产品片/概念片）

L1 只有 6 个模块，图生时只需改其中 3 处，其余照常：

| L1 模块 | 文生视频 | 图生视频（改这一列） |
|---|---|---|
| 整体风格 | 完整描述质感/色调/镜头 | **加材质母题声明**（`Material motif: ...`）+ 调色板身份（如 `Monochromatic dark palette with X accents`） |
| 场景概述 | 完整描述时间/地点/人物 | 改为**参考图锚定 + 环境恒定**：`from <Picture 1> in its original scene: ... The environment is constant throughout.` |
| 分镜 | 写主体动作 + 环境 | **重心转向运镜动词 + 光影互动**；Shot 1 加首帧锚定 `opens exactly on image 1`；主体动作可简（如 `resting confidently`） |
| 摄影机 | 运镜风格 | 照常（图生视频运镜更重要，参考下方运镜动词库） |
| 音频 | 照常 | 照常（图无声，音频全靠提示词） |
| 负面约束 | 一句话 | 强化"环境恒定""主体不变形""首帧一致"（归入一致性类） |

#### L2/L3 图生视频差异表（适用有角色资产/色卡等模块的等级）

| 模块 | 文生视频 | 图生视频 |
|---|---|---|
| 角色资产描述 | 详细逐件锁定（必须） | **大幅留白**——只写参考图无法体现的（动态气质、表情变化）；静态外观交给图 |
| 场景描述 | 完整描述 | 用 `in its original scene` + `constant throughout` 一句话锁定，不重复描述 |
| 分镜主体动作 | 详细写主体在做什么 | 重心转向**运镜 + 光影互动**，主体动作可简（如"resting confidently"） |
| 色卡/光影 | 完整色卡 | 声明**双色调/主光身份 + 调色板身份**即可（如 duotone blue+orange），细节交给图 |
| 负面约束 | 全面 | **强化"环境恒定""主体不变形""首帧一致"**（归入一致性类） |

### 恒定 vs 可变：环境恒定声明的边界

`The environment is constant throughout` 不是"什么都不能变"的开关。图生视频的关键张力是——**骨架恒定，血肉可变**：

| 恒定项（禁止漂移） | 可变项（允许甚至鼓励变化） |
|---|---|
| 背景虚空 / 表面材质 | 光的**强度与脉动**（slowly pulse brighter） |
| 色彩调色板身份（始终是蓝橙双色调） | 主体**位姿**（levitate / rotate / orbit） |
| 光源身份（哪几种光、从哪来） | **机位与焦段**（push-in / macro / beauty shot） |
| 整体风格气质 | 光与材质的**互动方式**（refract / sweep / flare） |

参考案例4：它同时声明了 `constant throughout`（环境恒定）和 `lights slowly pulse brighter`（光脉动）、`mouse levitates... rotating`（主体悬浮旋转）。恒定的是"pitch-black void + 暗反射面 + 蓝橙双色调身份"，变化的是"光强、主体位姿、机位"。

### 图生视频的负面约束补充

图生视频特有的 AI 崩坏模式，**全部归入"一致性禁止"分类**（与 modules.md #22 七大分类对齐，写入提示词的[严格禁止]→一致性类下）：
- **环境漂移**：背景在镜头间偷偷变化 → `The environment is constant throughout`（恒定的是上表"恒定项"）
- **主体变形**：参考图主体被 AI 改造 → `锁定参考图，主体形态不变`
- **材质丢失**：图里的透明/金属/折射材质在视频中变平 → 用材质母题反复强调
- **首帧偏离**（兜底）：已在特征0用正面陈述 `opens exactly on image 1` 强制；此处仅作兜底，可写"全程保持与参考图一致"

### 何时用图生视频范式

- 用户提供了产品图/角色立绘/场景概念图 → 必须用
- 用户要求"基于这张图做动效" / "让图里的东西动起来" → 必须用
- 纯文字描述、无任何参考图 → 用文生视频范式（本 skill 默认）

**判断信号——基于用户意图 + 主体描述密度，而非标记符号**：

`{{Mixed N}}` 和 `<Picture N>` 在 skill 里承担两种完全不同的语义，**不能仅凭符号判断**：

| 用法 | 名称 | 主体描述密度 | 是否触发留白 | 典型案例 |
|---|---|---|---|---|
| **图生视频型** | 让这张图动起来 | **低**——主体外观交给图，提示词大幅留白，只写运镜/光影/音频 | ✅ 触发 #32 留白原则 | 案例4（鼠标产品片） |
| **角色锁定型** | 多角色写实CG锁定 | **高**——仍详写服装/动作/发力链/特效，参考图只用于锁定外观一致性 | ❌ 不触发留白，照常详写 | 案例3（拳皇格斗） |

**区分标准**：
- 用户意图是"**让这张图动起来 / 基于这张图做动效**" + 主体描述**简略** → **图生视频型**（触发留白）
- 用户意图是"**做多角色戏，用参考图锁定角色外观**" + 主体描述**详尽**（服装/动作/特效都写了）→ **角色锁定型**（文生，不触发留白）

**保险做法**：如果不确定是哪种，直接问用户一句——"参考图是用来'让图里的东西动起来'（图生），还是用来'锁定角色外观、其余靠文字描述'（文生多角色）？"

## 33. 参考视频重绘（video-to-video / v2v）范式

**作用**：用户输入一段**源视频**，要求做风格重绘/延续。这是独立于文生和图生的第三范式——**运动也留白**。

**核心特征——比图生更激进的留白**：
- 图生视频：外观交给图，但**运动/运镜由提示词描述**
- v2v：**外观 + 运动都交给源视频**，提示词只写"风格覆盖层"（把源视频的写实风格重绘成什么调子）

**因此 v2v 强制降级到 L1 风格描述**：v2v 的提示词通常极短（几十词），只描述目标风格，不需要分镜/角色资产/动作逻辑等任何结构模块。如果用户为 v2v 选了 L2/L3，主动降级并说明原因。

**v2v 提示词写法**：
```
[目标风格] {风格描述：色调/质感/镜头语言关键词}
[覆盖指令] apply this style across all frames of the source video,
           preserve the original motion and composition
[保留项] keep {源视频里要保留的元素，如人物动作/场景结构}
[禁止] {不要改变的，如不要改变运动节奏/不要换主体}
```

**好的示例**（v2v 把写实街拍重绘为赛博朋克）：
> Transform this street footage into a cyberpunk aesthetic: neon-soaked palette of electric blue and magenta, wet reflective surfaces, volumetric fog, anamorphic lens flares. Apply across all frames while preserving the original camera motion and actor performance. Do not alter the movement pacing or replace the subject.

**v2v vs 图生 vs 文生的留白梯度**：

| 范式 | 外观 | 运动/运镜 | 提示词重心 | 典型长度 |
|---|---|---|---|---|
| 文生 | 提示词描述 | 提示词描述 | 一切 | L1~300字 / L3~5000字 |
| 图生 | 参考图锁定 | 提示词描述 | 运镜+光影+材质母题 | L1~300字 |
| **v2v** | 源视频锁定 | **源视频锁定** | **仅风格覆盖层** | **几十词** |

**平台支持**（2026年）：
- **Runway Gen-2/Gen-4**：Video-to-Video + Stylization 模式（最成熟，专门做风格迁移）
- **Kling**：支持视频参考输入做延续/重绘
- **Pika**：支持视频输入
- 多数平台的"Extend/视频续写"本质也是 v2v 的一种（延续运动而非改风格）

**判断信号**：用户提到"参考视频""基于这段视频""重绘""换个风格""视频转视频""video to video""stylize this clip" → 触发 v2v 范式。

## 34. 音频策略 [全等级]

**作用**：决定音频模块是**功能性的**还是**冗余 token**。这是 SKILL.md 第一步必问的维度，避免对静音平台写无效音频。

**为什么独立成维度**：不同平台/不同用途对音频的需求天差地别。在 Kling/Runway/Vidu 等静音模型上写"Audio: wind, footsteps, low score"是**无效甚至干扰**的 token；而 Sora 2 / Veo 3 / 可灵 2.1+ 等原生音频模型则需要精心设计的音轨。没有一个参数捕获这个意图，skill 要么写无用音频，要么靠用户事后纠正。

### 三档音频策略及处理方式

| 策略 | 何时选 | 音频模块怎么写 | 基础信息怎么声明 |
|---|---|---|---|
| **无声视频** | 目标平台不原生出声（旧版 Kling/Runway/Vidu/Pika），或用户明确不要声音 | **不写音频内容**（删除音频模块或留空） | 显式声明 `对白/字幕/水印/音乐：无`（消除AI默认行为，防止平台自作主张加BGM） |
| **平台原生音频** | 目标平台支持原生音频（Sora 2 / Veo 3 / Kling 2.1+ / Seedance / Wan 2.1+），用户要AI生成声音 | **正常写完整音频设计**（见 #24），强调分层/踩点/拟音/配乐爆发时间 | `音频：平台原生生成` + 详细音轨描述 |
| **后期自配** | 用户要后期自己配音/配乐，只要画面 | 音频模块写"仅画面，音频后期制作"或不写 | `音频：后期制作（视频不含音轨）` |

### 平台原生音频支持（2026年8月）

| 平台/模型 | 原生音频 | 备注 |
|---|:---:|---|
| **Sora 2 / 2 Pro** | ✅ | 同步对白、音效、音乐 |
| **Veo 3 / 3.1** | ✅ | 内置音频同步器，2026公认最强之一 |
| **Kling 2.1 / 2.5 / 2.6** | ✅ | 对话+音效 |
| **Seedance 2.0** | ✅ | — |
| **Wan 2.1 / 2.5** | ✅ | — |
| **Runway Gen-4 / 4.5** | ⚠️ 不同 | 音频处理方式不同，需查最新文档 |
| **旧版 Kling / Vidu / Pika** | ❌ | 静音，需后期 |

> **注意**：原生音频是2026年的快速演进能力，模型版本迭代频繁。**生成前务必确认用户所用平台/模型版本的最新音频能力**，不要依赖上表的静态信息。

### 默认推荐逻辑

用户未明确时，按以下默认：
- **平台=Runway/Vidu/Pika 或未指定 → 默认"无声视频"**（最安全，静音平台最多）
- **平台=Sora2/Veo3/Kling2.1+ 且未说后期 → 默认"平台原生音频"**（这些模型音频是卖点）
- **用户说"我自己配乐"/"后期配音" → "后期自配"**

**关键纪律**：选"无声视频"时，**必须保留基础信息里"音乐：无"的声明**——这比写一堆音频描述更重要，因为它直接阻止平台加默认BGM。

### 平台输出格式规则（负面约束的呈现方式）

不同平台对负面约束（negative prompt）的接收方式不同，影响最终提示词的**输出格式**：

| 平台 | 负面约束格式 | 处理方式 |
|---|---|---|
| **Runway / Pika** | **独立 negative 字段** | 把"严格禁止"模块的内容**抽成单独块**，填入平台的 negative 输入框；正向提示词里不再重复禁止项 |
| **Kling / Sora / Vidu / 通用** | **内联**（无独立字段） | 禁止项写在正向提示词末尾（如案例1的"No text, subtitles, logos..."一句），或用"不要/禁止"前缀融入正文 |

**组装时的分支**：如果用户选了 Runway/Pika，第四步输出时主动把负面约束拆成两块——`【正向提示词】`（主体内容）+ `【Negative Prompt】`（禁止清单），并在摘要里提示用户"负面约束已分离，请填入平台的 negative 字段"。其余平台保持内联。
